# 恋聊教练 · LoveChat Coach

**让回复更像你，也让下一步更清楚。**

贴一段聊天，或者讲清眼前的困惑，获得一条可发送的回复，以及给自己看的判断依据、下一步和停止条件。

v0.3 以 [狗头军师 goutoujunshi](https://github.com/shengjidaguai-china/goutoujunshi) 的方法架构为主体，提供可独立使用的 Agent Skill 和 Windows 微信桌面助手。桌面主流程已完成重构；真实模型生成质量与真实微信接入仍待验证，详见[当前状态](#当前状态)。

## 它能帮你做什么

| 你遇到的问题 | 选择模式 | 得到什么 |
| --- | --- | --- |
| “她这句话，我怎么自然地回？” | 帮我回复 | 一条符合本人口吻的正文，附发送时机、主要代价和后续分支 |
| “我该继续了解、说清楚，还是退出？” | 分析局面 | 可见事实、暂定解释、关键未知、首选行动与停止条件 |
| “我刚才那样说，哪里可以改？” | 复盘我的表达 | 一个做得好的点、一个最值得改的点，以及替代表达 |
| “陪我练一下邀约或冲突沟通。” | 陪我演练 | 每轮一条模拟回复，等你接话后再继续；模拟不代表对方真实想法 |

接话、情绪支持、邀约、关系确认、投入失衡、冲突、分手与家庭问题，都围绕具体情境处理。MBTI、依恋和主观评分可以作为背景，但不能替代真实行为，也不据此计算好感概率。

## 核心方法

```text
接住情绪
  → 分清事实、推测与未知
  → 看互惠、边界与现实条件
  → 选一个本轮主动作
  → 给出后续分支
  → 设定观察窗口与停止条件
```

- **依据原文判断**：事实引用本次可见的消息或本人提供的信息；推测保留依据和替代解释。
- **一次说清一件事**：承接、降压、调侃、轻推、约见、澄清、收线或安全支持，不把安慰、邀约和逼问承诺塞进一句话。
- **考虑后续怎么走**：对方积极、含糊、拒绝或没有回应时，分别给出下一步。
- **支持主动，也支持退出**：根据目标和反馈决定行动，不把得到某个人当作唯一结果。

“哈哈、好呀”和表情不自动等于暧昧。邀约会区分待回应、接受、拒绝、暂缓、改期待确认、取消、过期和完成；过期不会被当成已经见面，重复生成也不会刷新真实消息日期。

## 选一种开始方式

### 在 Agent 中使用 Skill

将完整的 [`skills/lovechat-coach`](skills/lovechat-coach) 文件夹放入宿主支持的技能目录，保留其中的参考资料与脚本，按宿主方式启用。若宿主支持 `$技能名`，可以这样开始：

```text
使用 $lovechat-coach。下面是我们的聊天，帮我分清事实和推测，
先给一条自然回复，再告诉我下一步以及什么时候该停。
```

Skill 可在当前对话中做关系分析、回复和演练。需要本机微信窗口、图形配置或本项目的精简档案工具时，再安装完整程序；只安装 Skill 不会自动装好这些功能。

### 使用 Windows 桌面助手

**需要 Windows 10/11、Python 3.11+，包含 Tcl/Tk，并将 Python 加入 PATH。** 目前是带图形安装入口的源码项目，尚无独立 EXE。

1. [下载完整项目 ZIP](https://github.com/ray404butworks/lovechat-coach/archive/refs/heads/main.zip)，解压到有写入权限的文件夹。
2. 双击根目录的 **恋聊教练.vbs**。首次需要联网安装依赖；不要直接在压缩包中运行。
3. 按引导选择模型、填写双方昵称、导入聊天，并设置本人风格、双方信息和关系目标。
4. 在 **军师方案** 页选择模式和场景，填写当前问题，点击 **保存模式与问题**。
5. 回到首页，按需粘贴对方来信，预览上下文并同意模型处理，点击 **生成本轮方案**。
6. 分别查看回复正文和军师建议；修改、核对后复制，自行发送。

分析、复盘和演练可以不填对方来信，将经过或自己的原话写在“当前问题”里。首次配置可保存进度，已有配置可在“接入与说明”中调整。详见[安装与首次配置](docs/share-installation.md)。

## 模型接入

| 接入方式 | 需要准备什么 |
| --- | --- |
| Codex / ChatGPT 登录 | 安装 Codex，并完成本机 ChatGPT 登录；程序不收集或复制登录令牌 |
| DeepSeek、OpenAI、Claude API | 本机填写 API Key 和服务当前可用的模型 ID；无需安装 Codex |

模型接入状态以实际调用结果为准。生成和整理历史会使用所选服务的额度，具体可用性取决于账号、网络和服务配置。

## 聊天历史与记忆

支持指定对象的 TXT/JSON 导入、重复导入去重、绑定文件同步、历史搜索，以及按需读取当前私聊画面。导入前核对对象、双方说话人、消息数量和时间范围。

| 数据层 | 保存与使用方式 |
| --- | --- |
| 原始文字历史 | 本机保存已导入记录；生成时选择近期和相关旧记录，可预览本次上下文 |
| 本人确认的资料与旧记忆 | 双方信息、关系目标、人设和共同经历分别维护，按对象使用 |
| 五层精简档案 | 本人、对象、关系、关键事件、暂定假设；默认未启用，启用后仍需核对候选再保存 |

精简档案保留来源，可查看、暂停、恢复、撤销、撤回同意或忘记对象。单条正文最多 200 字，总量最多 200 条；每个对象最多 20 条事件、5 条假设，保留最近 20 次撤销记录。生成本身不会自动保存候选。

精简档案与原始聊天、旧记忆分开；忘记精简档案中的对象不会同时清除原始聊天。升级沿用已有配置和数据，不默认开启新的档案功能。

## 隐私与使用范围

导入、检索、预览和档案控制在本机完成。生成回复、分析或整理历史时，相应聊天、资料和目标会发送给你选择的模型服务；可以先预览内容，再决定是否使用。

API Key 在本机遮蔽输入，使用 Windows 当前用户的 DPAPI 加密。私人配置、密钥、聊天记录、数据库和账号缓存不应上传 GitHub；共享源码请使用项目打包器，不要直接压缩整个工作目录。

程序没有发送按钮。生成、复制和模拟都不算已经发送，也不会推进真实关系状态。

目前不解读图片、语音、表情包和附件正文；未导入、未同步到电脑的记录不在覆盖范围内。微信 OCR 和可选历史读取器受客户端、系统及授权影响，不保证所有版本接通。可以先使用 TXT/JSON 导入和手动粘贴。
